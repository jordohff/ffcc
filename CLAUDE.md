# Fantasy Football Model

A weekly fantasy football projection model. Started 2026-08-09.

## Environment

## Data sources

- **nflreadpy** — primary source for historical stats: weekly player stats, schedules, snap counts,
  next-gen stats, etc. Pulled from the nflverse project. Returns **Polars** DataFrames by default
  (convert with `.to_pandas()` when we want pandas). This is the successor to `nfl_data_py`, which is
  no longer maintained — do not suggest `nfl_data_py`.
- **Sleeper API** — used for player ID/metadata mapping and injury designations only
  (`GET /v1/players/nfl`), via the officially documented endpoints at `https://api.sleeper.app/v1`.
  Deliberately NOT using Sleeper's stats/projections endpoints (`api.sleeper.app/stats/...`) —
  those are undocumented, unofficial, and could break without notice. If historical stats are ever
  needed from Sleeper specifically, ask the user first since this is a deviation from the current plan.
  No API key/auth needed for Sleeper.
- If/when the user wants projections tailored to their own Sleeper league (roster settings, scoring
  format), we'll pull their league data too — not done yet as of project start.

## Project structure

```
fantasy-football-model/
  src/ffmodel/        # importable package: data pulling, feature engineering, model code
  scripts/            # runnable entry points (uv run scripts/xyz.py)
  data/raw/           # cached raw pulls (gitignored, regenerate via scripts)
  data/processed/     # engineered feature tables (gitignored, regenerate via scripts)
  output/projections/ # generated projection CSVs (gitignored, regenerate via scripts)
```

Raw data, processed data, and outputs are all gitignored — they're regenerated by scripts, not
hand-edited or committed. Only code is committed.

## Modeling approach

- Starting point: a simple regression (nothing fancy) predicting weekly fantasy points from recent
  performance (rolling averages), target share, and matchup/opponent strength.
- Add complexity only when asked — this file should be updated if/when the modeling approach evolves
  (e.g. moving beyond linear/ridge regression, adding more feature sources).

### 2026-08-09 — initial build

- Scoring: model defaults to **half-PPR** (`--scoring half_ppr`). User has many leagues in both
  half-PPR and full PPR, never standard/non-PPR — so only those two are supported
  (`--scoring ppr` for full PPR). Half-PPR is derived as the average of nflreadpy's
  `fantasy_points` and `fantasy_points_ppr` columns rather than recomputed from scratch.
- v1 projections are a **backtest**, not forward-looking: train on earlier seasons, evaluate/predict
  on a recent holdout season (defaults to the most recent season pulled), output predicted vs. actual
  side by side. This was chosen over forward (next-week) projections to avoid needing schedule data
  and offseason team-change handling for v1. Forward-looking weekly projections (pulling
  `nfl.load_schedules()` for upcoming matchups) is a natural next step if wanted.
- Model: scikit-learn `Pipeline(SimpleImputer(median) -> Ridge regression)`. First run (train on
  2021-2024, test on 2025, half-PPR): MAE ≈ 4.2 fantasy points, R² ≈ 0.38. Sanity-checked — top
  week-1 2025 projections were recognizable stars (Gibbs, Taylor, Henry, Barkley, Mahomes), driven by
  strong trailing performance from the end of the prior season (rolling averages intentionally span
  the season boundary).
- Features are per-player trailing rolling averages only (`shift(1)` before every `rolling()`) to
  avoid leaking the target week's own stats into its own prediction. A player's first few tracked
  games (or a rookie's debut season) will have NaN features and get dropped — expected, not a bug.
- Data pulls are cached to `data/raw/*.parquet` and skipped on reruns unless `--force` is passed
  (`uv run scripts/pull_data.py --force`), per Sleeper's own guidance not to hit their player-list
  endpoint often.
